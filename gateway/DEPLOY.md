# 网关令牌（GATEWAY_TOKEN）实现说明

> 面向线上部署（交付部署方）的说明文档。
> 本文只陈述事实与部署要求，不含任何"官方推荐"表述。

---

## 一、它是什么

`GATEWAY_TOKEN` 是自建导航网关的**访问令牌**，用于挡住在网关上调用高德 Web 服务的外部请求，
保护服务端的 `AMAP_KEY` 不被人盗用、刷爆配额。

它**与高德无关**，是高德 Key 之外、由本项目自行设计的一层访问控制。

## 二、为什么需要这一层

架构链路：

```
App ──(带 GATEWAY_TOKEN)──▶ 自建网关 ──(带 AMAP_KEY)──▶ 高德 Web 服务
```

高德 Key 只存在于网关服务端，App 不接触 Key。
因此只要网关在网络上可被访问，任何能连到它的人都能间接使用你的 Key。
令牌的作用，就是给网关加一道"谁有资格用"的门槛。

## 三、实现机制

| 项           | 实现                                                                 |
|--------------|----------------------------------------------------------------------|
| 令牌来源     | 环境变量 `GATEWAY_TOKEN`，部署时自行生成，例如 `crypto.randomUUID()`   |
| 校验方式     | 每个请求头 `authorization: Bearer <GATEWAY_TOKEN>` 与服务端配置做**相等比较**；缺失或不匹配返回 `401 unauthorized` |
| 令牌性质     | 单一共享密钥（shared secret），全端统一，**无过期时间、无用户体系、非 OAuth** |
| 校验位置     | 网关入口 `gateway/src/server.js`，在解析业务参数之前先做认证，再走限流 |
| 失败即停     | 启动时检测到 `GATEWAY_TOKEN` 为空会直接拒绝启动（快速失败，不带着空配置运行） |

## 四、安全配套

- **Key / 令牌脱敏**：所有日志与错误响应经 `redact()` 处理，任何路径不回显 Key 或令牌内容；
  `/health` 只返回 `hasKey` 布尔值。
- **限流**：默认 60 次/分钟（可配 `RATE_LIMIT_PER_MIN`），防止误用刷爆高德配额。
- **请求体上限 8KB**、仅放行已知端点，其余一律 404。
- **无缓存层**：遵守高德协议禁止存储 / 缓存服务数据的要求。

## 五、部署时需要做的事

1. 部署环境注入两个必填环境变量：
   - `AMAP_KEY`：高德「Web 服务」类型 Key。
   - `GATEWAY_TOKEN`：自行生成（例如 `node -e "console.log(crypto.randomUUID())"`）。
2. 网关当前默认监听 `127.0.0.1:8080`。
   若要暴露给 App 访问，需让其绑定可访问的地址 / 端口，并确认令牌已配置。
3. App 侧每次请求都需附带 `authorization: Bearer <GATEWAY_TOKEN>` 请求头。

## 六、给线上部署的提醒

> ⚠️ 当前实现为**共享密钥 + 明文等值比较 + 永不过期**，定位是**个人自用、单一客户端**。

令牌一旦写进分发的 App，严格意义上也处于"可反编译提取"的境地；
它的作用是**提高盗用门槛、挡住随手扫描**，而非强认证。

若线上部署要面对公网 / 多用户 / 分发场景，建议补强其一：

- **令牌轮换或加过期时间**；
- **来源 IP 白名单**；
- 或改用短期令牌 / mTLS 等更强机制。

以降低共享密钥泄露后等同于 Key 泄露的风险。
