# 电子相框（图片 / GIF 播放）+ SD 卡管理：设计方案 v2

> **状态**：**设计稿，待评审** —— 本文不含代码改动。
>
> **v2 变更**（2026-10-19，按用户要求）：**不做"照片表盘"**，改为
> **独立的「电子相框模式」** —— 纯照片展示，不叠加时钟/速度，不参与表盘滑动。
>
> v1 里关于**传输速度**与**格式选择**的论证仍然成立，已保留；
> 表盘相关的章节已删除，新增**相框模式的状态机**与**AMOLED 烧屏防护**（见 §5）。

## 一、需求（v2 定稿）

| # | 需求 | 说明 |
|---|------|------|
| A | **纯照片展示** | 不叠加时钟/速度/导航。**当作电子相框** |
| B | **GIF 动图** | 同一个相框里能放动图 |
| C | App 内 **裁切 + 预览**；**动图转 GIF、视频转 GIF** | 全部 iOS 内置框架 |
| D | App 端 **SD 卡状态 / 管理** | 看容量、列文件、删除（格式化待定，见 §8）|

**已明确不做**：

- ❌ 照片表盘（不注册进表盘列表、不参与滑动）
- ❌ 照片上叠加时钟/速度
- ❌ 设备端解码 GIF / PNG / JPEG（理由见 §3）

## 二、硬约束（沿用 v1，已核实）

### 2.1 资源

| 资源 | 现状 | 余量 |
|------|------|------|
| Flash（3 MB 分区）| 1,901,259 B（60%）| **约 1215 KB** |
| PSRAM（8 MB）| 5 张烘焙图约 1.4 MB | **约 6.5 MB** |
| SD 卡 | SDHC 7.3 GB | **可用 5.74 GB** |

> **一帧全屏 RGB565 = 424 KB** —— Flash 装不下图片。**必须用 SD 卡**（与 D-010 一致）。

### 2.2 单帧体积

| 格式 | 每帧 |
|------|------|
| RGB565 原始 | 424.1 KB |
| **8bpp 索引** | **212.1 KB**（+1 KB 调色板）|
| 8bpp + RLE（2:1）| 约 106 KB |
| 240×240 8bpp | 56.2 KB |

### 2.3 传输速度（**最硬的约束**）

**BLE 实测有效吞吐约 1 KB/s**（依据：地图窗口 50 条消息要 2~3 秒、每条 ≤180 B）。

| 传什么 | BLE 需要 |
|--------|---------|
| 全屏单张（212 KB）| **212 秒** |
| **10 帧 GIF（2.1 MB）** | **约 35 分钟** ✗ |

> ### 🔴 结论 1：图片/GIF **不可能走 BLE**，必须换通道（§6）

### 2.4 设备端解码与刷新

| 环节 | 成本 | 来源 |
|------|------|------|
| 索引图逐像素解码（LVGL 内置）| 全屏 **+45 ms** | `ui_img_inflate.c` 真机实测 |
| 全屏 flush（QSPI 80 MHz）| **43 ms** | PROGRESS §六 |

> ### 🟡 结论 2：动画帧率 **全屏 7~11 fps**；240×240 可达 **20~30 fps**

### 2.5 🔴 **AMOLED 烧屏**（v2 新增，**电子相框的关键风险**）

面板是 **CO5300 AMOLED**（`docs/hardware.md`）。AMOLED 的烧屏是**永久性**的：
**同一静止画面（尤其高亮、高对比区域）长时间显示，会在面板上留下不可逆的烙印。**

电子相框恰恰是"长时间显示静止图片"的用法 —— **这是本方案最需要防的东西**，
不是可选项。防护见 **§5**。

## 三、核心思路（与 v1 相同）

> **设备端不给 GIF/PNG/JPEG 解码器，所有重活都在 App 做。**

S3 **无硬件 JPEG 解码**，软解 466×466 要 50~100 ms → 动画不可行。
而项目**已有 8bpp 索引图解码**（`img_indexed`，28 项测试）与
**索引图 → PSRAM RGB565 充气**（`ui_img_inflate`）—— 相框就是**同一条思路的流式版**。

## 四、设备端设计

### 4.1 格式：`.pgi`（Photo/GIF Indexed，多帧）

```
┌ 文件头 32 B ─────────────────────────────┐
│ magic "PGI1" | 宽 u16 | 高 u16            │
│ 帧数 u16 | fps u8 | flags u8（bit0=逐帧调色板）│
├ 调色板 256×4 B（全局一份，或每帧一份）────┤
├ 帧索引表（帧数 × 8 B）───────────────────┤
│ 每帧：偏移 u32 | 长度 u32                  │
├ 帧数据（8bpp 索引流，可选 RLE）───────────┤
└──────────────────────────────────────────┘
```

- **单帧 = 静态照片**，**多帧 = GIF 动图** —— **一个格式统一两种内容** ✓
  相框只管按 fps 翻帧：`帧数 == 1` 就是静止图。
- **设备端只解索引色**（查表/memcpy），**不解 GIF/PNG/JPEG**。
- RLE 留作后补（等 §10 的 S1 实测读速再定）。

### 4.2 相框模式：**全屏覆盖层，不是表盘**

⚠️ **不能做成第 6 个表盘**：`ui_pages` 是**横向滚动容器**（`ui_pages.c`），
加一页它就会进入**滑动序列**，而用户要的是"临时进入一个相框"，不是"多一个可划到的表盘"。

**做法**：在同一个 screen 上创建/举起一个**全屏覆盖对象**（`lv_obj_create` + 置顶），
同时**禁用滚动容器**；退出时删除覆盖层并恢复。

```
[仪表正常]  ──BLE/串口"进入相框"──▶  [相框覆盖层（置顶、全屏）]
                                      ↑ 幻灯片 / GIF 动画
     ▲                                │
     └────── 退出（含自动退出）────────┘
```

**为什么用覆盖层而不是新建 screen**：项目的页面切换、触摸坐标、旋转补偿都建立在
现有的单 screen 上；新建 screen 要重做这些，收益却为零。

### 4.3 相框的状态机

```
        ┌─────────────────────────────────────────┐
        │                                         │
   [仪表] ──enter──▶ [相框·播放] ──下一张──▶ [相框·播放] ──exit──▶ [仪表]
                        │
                        └── 幻灯片间隔到 ──▶ 切下一张
```

**进入**：三种入口，见 §4.4。

**退出**（必须有多重保证）：

| 触发 | 说明 |
|------|------|
| BLE / 串口 `exit` | 主动退出 |
| **触摸屏幕任意位置** | 最直观的"退出手势" |
| **收到真实遥测 / 开始驾驶** | ⚠️ **安全兜底**：仪表是开车看的，**开车时绝不能停在相框模式** |
| **自动息屏时间到** | 见 §5 |

> 最后一条和演示速度的退出机制**是同一个模式**（固件自己兜底，不依赖 App 记得发命令）——
> 那次踩过的坑（App 命令丢了就卡在错误状态）不重演。

### 4.4 入口设计（需你确认，见 §8）

| 入口 | 优点 | 缺点 |
|------|------|------|
| **App 上的按钮**（BLE 命令）| 直观、可远程 | 依赖 BLE 连接 |
| **串口 `photo` 命令** | 开发/调试必备 | 日常用不到 |
| **长按屏幕** | 不依赖 App | 容易误触（且和滑动/点击冲突）|
| **无操作 N 分钟后自动进入** | 真正的"相框"体验 | 要判断"用户不在用" |

**建议**：**App 按钮 + 串口命令**先做；**长按 / 自动进入**作为可选增强。

### 4.5 幻灯片

- **多张照片轮播**，间隔可配（默认 **30 秒**）；
- 顺序：**文件名排序**（用户可以用 `01_xxx.pgi`、`02_xxx.pgi` 自己排）；
- **单个 GIF**：播放其帧 → 播完**循环 2 次**后切下一张（避免一张动图霸屏）；
- **切换效果**：**先做直接切换**（淡入淡出在 466×466 上要额外两帧缓冲，收益不大）。

### 4.6 资源占用

| 项 | 占用 |
|----|------|
| 帧缓冲（双缓冲，全屏 8bpp→RGB565）| 2 × 424 KB ≈ **850 KB PSRAM** |
| 现有烘焙图 | 1.4 MB |
| **合计** | 约 2.3 MB / 8 MB ✓ **余量充足** |

**不做"预解码全部帧"**：10 帧就要 4.2 MB，且大 GIF 会直接把 PSRAM 吃光。

## 五、🔴 AMOLED 烧屏防护（v2 的核心新增）

电子相框 = 长时间静止画面 = **AMOLED 最怕的用法**。四道防护，**默认全开**：

| # | 措施 | 说明 | 可配 |
|---|------|------|------|
| 1 | **幻灯片轮播** | 画面整体变化是最好的防烧屏 | 间隔 10~300 s |
| 2 | **像素位移（pixel shift）** | 每隔 **2 分钟**把画面整体平移 **±3 px**（四周各裁 3 px，不会露边）| 开关 |
| 3 | **亮度上限** | 相框模式下亮度**封顶 180**（比正常暗一档，显著延缓老化）| 开关 |
| 4 | **自动息屏** | **30 分钟**无触摸且无 BLE 交互 → 息屏（可再触摸唤醒）| 时长可配 |

> **另外两条必须写进实现**：
>
> - 若只有 **1 张**照片且不开轮播 → **强制开启像素位移**（否则等于静态烙印）；
> - 相框模式**禁止长期停在纯白/纯亮画面**（例如用户传了一张白底图）——
>   这种情况**降低亮度上限**或提示用户。

## 六、传输：**先 SD 卡插拔，目标 Wi-Fi**

| 方案 | 用户操作 | 速度 | 判断 |
|------|---------|------|------|
| **A. SD 卡插拔** | 拔卡 → 电脑 → 拷到 `/photos/` → 插回 | 快 | ✅ **先做**（固件几乎零成本）|
| **B. Wi-Fi 上传** | App 点"上传"→ 等几秒 | **500 KB/s 量级**（2 MB GIF < 5 秒）| ✅ **目标形态** |
| C. BLE | — | 1 KB/s | ❌ 不可用 |
| D. USB MSC | 插线 → 电脑出现盘符 | 快 | ⚠️ 与现有 CDC 串口冲突，备选 |

**B 的风险（必须先 spike）**：本板是 **octal PSRAM（opi）**，S3 上 PSRAM 与 Wi-Fi 有
已知的带宽/稳定性权衡。验证项：开 AP + HTTP 传 1 MB，检查 ① 不崩 ② LVGL 仍正常 ③ 实测吞吐。

**B 的安全设计**：AP 默认关闭、只在被 BLE 命令触发后开启、**5 分钟无操作自动关**、
随机密码（屏幕上显示 + BLE 告知 App）、只允许写 `/photos/`、只接受一个客户端。

## 七、App 端设计

### 7.1 裁切 / 预览 / 转 GIF（需求 C，全内置框架，零依赖）

| 功能 | 框架 |
|------|------|
| 选图 / 选视频 | `PhotosPicker` |
| **裁切 + 圆屏预览** | `UIGraphicsImageRenderer` + 手势；**466×466 + 圆形遮罩，所见即所得** |
| **动图 → GIF** | `CGImageSource`（GIF / APNG / WebP / Live Photo）|
| **视频 → GIF** | `AVAssetImageGenerator` 抽帧 → `CGImageDestination` 写 GIF |
| **GIF → `.pgi`** | App 内量化 + 打包 |

> **转码放 App** 的理由：App 有完整算力；设备固件因此**只做 memcpy**；
> 也不需要给网关加 `sharp` 之类的服务端依赖。

### 7.2 App 的相框页（新增）

```
┌ 电子相框 ─────────────────────┐
│ [进入相框]  [退出]             │  ← BLE 命令
│ ─────────────────────────     │
│ 幻灯片间隔  [30 s ▾]           │
│ 像素位移    [开]               │
│ 亮度上限    [180]              │
│ ─────────────────────────     │
│ SD 卡：SDHC 7.3 GB / 可用 5.74 GB │
│ [刷新] [列出照片]              │
│ 📄 01_sunset.pgi   212 KB      │
│ 📄 02_cat.pgi      1.8 MB      │
│ [删除所选]                     │
└───────────────────────────────┘
```

### 7.3 SD 卡管理（需求 D）

**现状**：SD 信息只能靠**串口** `sd` 看，App 完全看不到。

**新增 BLE 命令**（草案）：

| 操作 | 消息 | 设备行为 | 风险 |
|------|------|---------|------|
| 查状态 | `{"cmd":"sd","op":"info"}` | 回挂载状态、类型、总容量/可用、照片数 | 无 |
| 列文件 | `{"cmd":"sd","op":"list"}` | 分页返回 `/photos/` 的文件名与大小 | 无 |
| 删除 | `{"cmd":"sd","op":"del","name":"a.pgi"}` | 只允许删 `/photos/` 内的 | 低（删了找不回）|
| **格式化** | `{"cmd":"sd","op":"format"}` | 需双重确认 | **🔴 极高** |

> **格式化我建议不做**（§8 #5）—— 风险/收益不划算，交给电脑。

## 九、分阶段实施

| 阶段 | 内容 | 可验收标准 | 依赖 |
|------|------|-----------|------|
| **P0** | 定 `.pgi` 规格 + **Mac 侧生成器** `tools/pgi.py`（PNG/GIF → `.pgi`）| PC 单测：`.pgi` 解回原图**逐像素一致** | 无 |
| **P1** | **相框模式 + 静态图**：覆盖层 + 读 SD `/photos/*.pgi` 显示首帧 + 触摸/命令退出 | 插卡 → App 点"进入相框" → **看到照片**；触摸屏幕**退出** | P0 |
| **P2** | **GIF 动画**：多帧 + 双缓冲 + 只在相框可见时跑 | 播放 10 帧动画 **≥8 fps**；切走立即停 | P1 |
| **P3** | **幻灯片 + 烧屏防护**（轮播/位移/亮度上限/自动息屏）| 单张照片 **2 分钟后可见整体位移**；30 分钟自动息屏 | P2 |
| **P4** | **App 裁切 / 预览 / 视频转 GIF**（纯 App，无硬件依赖）| 选一段视频 → 裁切预览 → 导出 GIF 到相册 | 无（可并行）|
| **P5** | **SD 管理**（状态/列表/删除）| App 能看到容量与文件列表；删除后 `sd list` 同步 | 需传输通道 |
| **P6** | **Wi-Fi 上传**（若 §六 的 spike 通过）| 传 2 MB GIF **< 30 秒**；AP 5 分钟自动关 | P2 + spike |

> **P4 可以先做**（纯 App ✓ 立刻有产出 ✓）；**P1 也能先做**（SD 插拔就够 ✓ 不必等 Wi-Fi ✓）。

## 十、开发前必须先验的 Spike

| # | 验证 | 怎么验 | 不行的退路 |
|---|------|--------|-----------|
| **S1** | SD 卡 1-bit 读速 | 串口命令读 1 MB 计时 | 上 RLE / 降分辨率 |
| **S2** | Wi-Fi + octal PSRAM 共存 | 起 AP + HTTP 传 1 MB | 退回 SD 插拔 + USB MSC |
| **S3** | 全屏解码 + flush 真实耗时 | 计时打印 | 限定 240×240 |
| **S4** | PSRAM 双缓冲（850 KB）+ 现有 1.4 MB 余量 | `mem` 观察 | 减缓冲 / 单缓冲 |

> **S1+S3 约半天**，只需串口命令与日志，不动 UI。**建议先做这两个再定 P2 的 fps。**

## 十一、明确不做

| 不做 | 原因 |
|------|------|
| 照片表盘（进滑动序列）| 用户明确要"纯相框"，且会污染表盘列表 |
| 照片上叠加时钟/速度 | 同上 |
| 设备端解 GIF/PNG/JPEG | 无硬件解码，软解太慢（§3）|
| 图片进 Flash | 余量 1.2 MB，装不下一帧 |
| BLE 传图片 | 1 KB/s，动图要半小时（§2.3）|
| 淡入淡出切换 | 466×466 上要多两帧缓冲，收益不大 |
| SD 格式化（建议）| 风险/收益不划算（§8 #5）|
| 云端相册 / 多设备同步 | 与"个人自用"定位无关 |

## 十二、与既有决策的关系

| 决策 | 影响 |
|------|------|
| **D-010**（SD 卡给字模；地图放手机）| ✅ 完全一致：**SD 卡就是给照片/GIF 的** |
| **D-009**（参考项目只学设计不抄代码）| ✅ `.pgi` 是本项目自定的格式 |
| **§6.3**（不得把非真实数据当有效显示）| ✅ 相框是**用户主动进入的装饰模式**，不冒充数据 |
| **演示速度的"三重退出"** | ✅ 相框沿用同一模式：**收到真实遥测/开始驾驶 → 自动退出** |

> ⚠️ **一条安全边界要写进实现**：相框模式是"停车看照片"的用法。
> **收到真实遥测（即开始驾驶）必须自动退出** —— 别让装饰影响行车可用性。
