# 技术决策记录

记录本项目关键决策及原因。每条决策注明日期、依据与影响。

## D-001 主构建路线：Arduino IDE + Arduino-ESP32 Core

- **日期**：2026-10-10（里程碑 0）
- **决策**：以 Arduino IDE 2.3.10 作为主构建/烧录工具，Arduino-ESP32 Core **3.3.10**（espressif）作为平台。
- **原因**：
  1. `AI_CONTEXT.md` 建议初期降低环境复杂度，先跑通官方示例。
  2. 官方仓库（commit `e4344e7`）的 Arduino 示例明确验证于 Core 3.3.10。
  3. 微雪官方 Arduino 示例覆盖屏幕/触摸/RTC/IMU/GNSS/SD 全部所需外设，可直接增量开发。
- **影响**：不引入 ESP-IDF、PlatformIO 等第二套构建体系；若日后切换框架，先评估迁移成本再行动。
- **状态**：已定。

## D-003 编译配置：16MB Flash + app3M_fat9M_16MB 分区

- **日期**：2026-10-10
- **决策**：FQBN 统一为
  `esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=app3M_fat9M_16MB`
- **原因**：官方快速开始明确要求该组合（Flash 16MB、分区 `app3M_fat9M_16MB`）；与官方 Release 固件布局一致，避免混用布局导致启动问题。
- **状态**：已定。所有示例验证与业务固件均使用此配置。

## D-004 配套库使用方式：随仓库 `examples/arduino/libraries`

- **日期**：2026-10-10
- **决策**：编译示例/固件时用 `--libraries reference/ESP32-S3-Touch-AMOLED-1.75/examples/arduino/libraries` 指定随仓库配套库，保证版本配套。
- **原因**：官方文档明确建议；避免与全局库副本版本冲突（若 IDE 内有冲突的全局副本，删除或降低其优先级）。

## D-005 UI 框架：LVGL

- **日期**：2026-10-10（初定）
- **决策**：图形界面使用 LVGL（版本随官方配套库，不单独升级）。
- **原因**：官方示例均基于 LVGL，触摸、圆形屏适配已有现成代码；单独升级 LVGL 版本会带来与板级驱动的不兼容风险。
- **状态**：初定，随里程碑 2 落实。**具体版本：LVGL 8.4.0**（官方 `examples/arduino/libraries/lvgl/library.properties`）。

## D-006 UI 设计路线：模拟器为主 + SquareLine 仅作草稿参考

- **日期**：2026-10-10
- **决策**：UI 开发主路线为 **AI 手写 LVGL 8.4 C 代码 + macOS SDL 模拟器预览**（`simulator/`）；
  SquareLine Studio 不作为主路线，如需拖拽草稿仅作布局参考，导出代码不直接进固件。
- **原因**：
  1. SquareLine 1.6.2 的 LVGL 8.x 导出只支持到 **8.3.11**，**不支持 8.4**；8.3 导出码 + 8.4 运行时属未验证混搭，违反第 5 节版本配套原则。
  2. 迁就 SquareLine 换 LVGL 9（或降 8.3）都会偏离官方验证路径，屏幕/触摸/RTC/GNSS 示例全部重验，得不偿失。
  3. 模拟器与固件同版本（8.4.0）同 API、同色深（RGB565 16bit）、同分辨率（466×466），预览即真机所得；UI 代码可原样移植进 Arduino 工程。
  4. SquareLine 是图形工具，AI 无法代为操作；且它不负责 RTC/GNSS 数据接线，该部分本就要手写。
- **许可说明**：SquareLine Personal 免费版限非商业用途、10 屏幕/150 控件，本项目范围内够用（若仅作草稿参考）。
- **状态**：已定（用户 2026-10-10 确认）。

### D-006 附注：LVGL Pro 评估（2026-10-10）

- **事实**（[lvgl.io/pro](https://lvgl.io/pro)）：LVGL 官方新产品，XML 界面编辑器，
  支持像素级**实时预览** + Inspector、[浏览器在线编辑 viewer.lvgl.io](https://viewer.lvgl.io/)、
  Figma 导入、CLI 代码生成；Community 档**免费**（个人/开源，无 CLI）。
- **结论**：实时预览能力优于 SquareLine；但其 XML/代码生成面向 **LVGL 9.x**，
  本项目固件为 LVGL 8.4.0，导出代码同样不能进固件——与 SquareLine 同类版本不匹配，主路线不变。
- **保留价值**：XML 是纯文本、Git 友好、明确面向 AI 辅助开发；若日后需要更强的草稿工具，
  LVGL Pro（免费档）优于 SquareLine。**观察项**：微雪若将 Arduino 配套库升级到 LVGL 9，
  LVGL Pro 可升级为一等选项（支持设备端 XML 运行时加载），届时重新评估本决策。

## D-010 地图资源与字模的存放位置：**地图不放设备，SD 卡给字模**

- **日期**：2026-10-14
- **决策**：
  1. **周边地图数据不走设备 SD 卡**。地图走"**手机/网关侧持有数据 → 只把当前位置
     附近约 500 米的几何窗口经 BLE 发给设备**"这条路线（阶段 1 用网关在线矢量瓦片；
     若日后需要离线，再做手机侧区域离线包）。
  2. **设备 SD 卡（实测 SDHC 7.3 GB，可用 5.74 GB）的用途是中文字模**、图片素材、行程日志等
     **设备本地资源**，而不是地图。
- **决定性原因**：**本板无 GNSS**（`ESP32-S3-Touch-AMOLED-1.75`，非 `-G` 版），
  位置数据 **100% 来自 iPhone**（见 [hardware.md](hardware.md)）。
  - **没有手机 → 设备没有坐标 → 不知道该显示哪一块地图**；
  - **有手机 → 手机本身就有大得多的存储与算力**。
  - 因此把地图放设备 SD 卡**无法让设备独立工作**，只是徒增设备负担
    （要在 ESP32 上做矢量解码 + 空间查询）。
- **与参考项目一致**：moto-gps-waveshare 的离线地图文档明确写着
  "终端仍只接收当前窗口，**不需要把 9.73 MiB 全市数据放进 ESP32**"，
  其离线包（全济南 SQLite + R-tree）放在**手机**侧。我们沿用同一分工。
- **数据源约束**（重要）：
  - 环境图层（灰路/灰楼）**不能用高德** —— 其协议 §3.5 禁止"存储、缓存或抓取
    本服务内部数据、图片"。高德只用于**实时路线与搜索**。
  - 阶段 1 采用 **OpenFreeMap 矢量瓦片**（免费、无 Key，官方允许离线下载
    ≤3000 瓦片/次、≤50MB、最多 4 并发、需唯一 User-Agent）。
  - 若日后做**区域离线包**，数据源应走 **Geofabrik PBF 提取**，
    **禁止**批量下载 `tile.openstreetmap.org` 瓦片来制作离线包
    （这是参考项目踩过的坑，见其 offline_map 文档）。
  - **署名义务**：界面或"关于"页须提供可见的 `© OpenStreetMap contributors`
    与 ODbL 许可链接。
- **备选方案（已评估，暂不采用）**：
  - **设备 SD 卡存地图**：设备自解码 + 自查询。可脱离手机也显示底图，
    但**位置仍需手机**，收益低、代价高。
  - **手机生成地图图片经 BLE 传图**：带宽紧张（466×466 深色地图压缩后
    约 10–60 KB/帧 × 1 Hz），会与遥测/导航争带宽，且清晰度受压缩限制。
- **状态**：已定（阶段 1 的网关接口已实现并实测：首查 1.68 s、缓存后 7 ms、
  窗口约 2.2 KB）。

## D-011 照片导入：**SD 卡**，放弃 Wi-Fi 上传

- **日期**：2026-10-19
- **决策**：照片表盘（id 5）的素材导入走 **SD 卡**（`tools/import_photos.sh` →
  `/photos/*.pgi`）；**不做** Wi-Fi/HTTP 上传。切图与轮播设置走 **BLE**。
- **原因（实测，不是估计）**：手机连上设备热点后，内部堆从 ~104 KB 掉到
  **2~4 KB** —— Wi-Fi 协议栈本身吃掉 50 KB+，**PSRAM 帮不上忙**（Wi-Fi/`String`
  只能用内部 RAM）。换掉 `WebServer`、改裸 `WiFiServer` 也几乎没变化。
  完整证据链：[wifi-upload-postmortem.md](wifi-upload-postmortem.md)。
- **影响**：
  - 加/删照片要拔卡（无 App 内入口）；`.pgi` 体积上限放宽到 40 MB（仅防手滑）；
  - 保留 `GET /list` / `POST /delete`（几百字节堆即可用），只放弃 `POST /upload`；
  - 帧率受 SD 读速限制（满屏 3~4 fps），需要更流畅用 `--fast` 缩图。
- **状态**：已定（用户确认"能用就行，不折腾 Wi-Fi"）。

## D-012 表盘列表上报：**紧凑名字数组**（受 BLE 184 字节硬上限约束）

- **日期**：2026-10-20
- **决策**：`Faces` 特征只发**表盘名数组**（顺序即 id），不再发对象数组：
  `{"t":"f","c":6,"m":63,"u":5,"bright":200,"rot":0,"screen":1,
  "f":["analog","digital","speed","color","nav","photo"]}`（约 173 字节）。
  App 自行推导 `id`/`group`/`on`，并**同时兼容旧格式**。
- **原因**：iOS 单次 BLE 读取上限约 **184 字节**，对象格式 6 个表盘要 **476 字节**
  → 必被截断 → 表现为"表盘列表不完整/照片表盘消失/一个表盘都没有"。
  压到 371 仍不够，只能换结构。
- **影响**：
  - 新增表盘时**不再需要改 App**；但表盘多到 184 字节装不下时，要改用 Read Blob 分片；
  - 设备侧 `label` 字段不再上报，App 未收录的 `name` 直接原样显示。
- **状态**：已定（真机验证 173 字节、6/6 表盘）。

## D-013 速度表驾驶员三态阈值：**80 / 110 km/h**

- **日期**：2026-10-20
- **决策**：中央驾驶员插画按车速三态切换 ——
  `0~80` 平静（`driver_normal`）、`80~110` 皱眉（`driver_spirited`）、
  `>110` 咬牙（`driver_speeding`）。
- **演进历史**（三次调整，都是为了"表情要对得上现实限速"）：

  | 版本 | 阈值 | 问题 |
  |------|------|------|
  | 初版 | 90 / 120 | 高速上 100 km/h 还一脸平静，不符合"已经开得快"的直觉 |
  | 第二版 | 60 / 100 | 矫枉过正：城市快速路 80 km/h 就皱眉，几乎全程"生气" |
  | **现行** | **80 / 110** | 对齐现实：80 = 快速路限速，110 = 高速偏快（120 才是超速） |

- **实现**：`simulator/ui/ui_speed.c` 的 `DRIVER_SPIRITED_V` / `DRIVER_SPEEDING_V`；
  只在**跨阈值**时 `lv_img_set_src`（变更检测，避免每帧重设图片）。
- **状态**：已定（真机 + 模拟器截图验证，见 `docs/images/speed-3stages.png`）。
